12The Design System — Cyber Aqua in Two Moods

One 3,610-line stylesheet is the design system: 111 design tokens, 231 component classes, 33 keyframes, and a set of standing rules — most famously, no purple or violet, and no gold, anywhere, ever. This chapter documents the current Cyber Aqua canon and the earlier design eras — Soft Pastel, electric green, and the rest — as history.

A design language and its evolution

The project's canonical description (in docs/AGENT_MEMORY.md) names the current design language Cyber Aqua: a deep-space canvas with a neon cyan accent, expressed as "two moods of the same room": Paper (bright day) and Ink (dark night). The palette is electric cyan (#06B6D4) and teal (#0891B2) as the accent family, hot pink (#EC4899/#DB2777) as the companion, emerald (#10B981/#059669) for success, on a near-black canvas (#0A0A0F) by day and near-white paper (#FAFAFA) by light mode. That canon is the survivor of many rejected passes the changelog records candidly — a gray "Still Ink" pass the owner called bland, a blurple pass rejected for violating the standing rule against violet, and the Soft Pastel and electric-green systems that preceded Cyber Aqua.

The stylesheet has kept evolving since. The 2026-07-30 redesign (PR #280) re-skinned the product as Cyber Aqua: the accent moved from electric green to neon cyan, the third "Dusk" mood was retired permanently (the twilight/dusk values were deleted from types/index.ts, lib/themes.ts, preferenceStore, the layout's theme script, and every globals.css selector), and a single brand gradient (--accent-gradient: linear-gradient(135deg, #06B6D4 0%, #EC4899 100%)) now runs cyan-to-pink. The result in the working tree is unambiguous: type Theme = "light" | "dark", and THEME_OPTIONS lists exactly two rooms — Paper, "Clean cyan, airy vibes", and Ink, "Deep space, neon cyan glow". The two-mood structure is the system's architecture (theme blocks keyed off data-theme, with every surface derived from tokens); earlier moods are retired rather than architecturally possible.

Beyond colors, the sheet tokenizes shadows (--shadow-sm/md/lg, plus glow variants like --shadow-glow-accent), glassmorphism parameters (--glass-blur: 16px, --glass-saturate: 120%, --glass-edge), line heights (--leading-tight: 1.15 to --leading-relaxed: 1.75), durations (--dur-fast: 120ms to --dur-slow: 300ms), the scrim, and subject colors (--subject-physics through --subject-general) that tint the part-card chips. Tailwind's config maps its own color names onto these variables (accent: "var(--accent)", background: "var(--bg-primary)"…), so utility classes stay theme-correct without duplication.

The moods in practice

Ink is the :root default block: deep-space off-black canvas #0A0A0F, zinc cards #18181B, near-white ink #FAFAFA, neon cyan #06B6D4 with white text on CTA fills and hot pink #EC4899 as the companion. Paper — the html[data-theme="light"] override block — is a bright near-white canvas #FAFAFA, white cards, deep ink #18181B, teal cyan #0891B2 with hot pink #DB2777 companion. Ink is the default theme for new users ("Ink is the default room", per preferenceStore). A third "Dusk"/teal-sunset evening mood existed until the 2026-07-30 Cyber Aqua redesign concluded that two fully curated themes beat three partially distinct ones; the picker labels, the layout's pre-paint script, and the type union all now enumerate exactly Paper and Ink. Theme switching is instant and flash-free: the pre-paint script in layout.tsx sets data-theme before first paint, ThemeApplier keeps it and the theme-color meta in sync afterward, and every one of the 231 component classes reads only tokens, so a mood change is one attribute write.

The rules: no purple, no gold, no hardcoded hex

Two constraints have outlived every visual pass. The first is documented in AGENT_MEMORY as an owner's standing rule: no purple or violet anywhere. It has been enforced by action — the changelog records a dedicated "Purple/Violet Purge" that removed "40+ purple/violet/indigo color violations" introduced by a single PR across twelve files, re-skinning theme pickers, the logo, the manifest colors, badge tiers, share-card orbs, and confetti palettes. The same owner's rule also bans gold. A grep of the current token sheet confirms compliance: the palette is cyan, teal, hot pink, emerald, the red/green feedback pair, and zinc neutrals. The second constraint is the "one accent, used sparingly" de-slop rule, which keeps the cyan concentrated on primary actions, active states, and progress indicators rather than washed over everything; the soft-brand gradient (--accent-gradient) is reserved for the logo and hero glow.

Classes, not inline styles

The memory document calls inline style={{ ... }} soup "the #1 thing that makes this codebase look AI-generated" and mandates the component classes instead: .btn-primary, .btn-ghost, .btn-icon, .chip, .nav-link, .rl-card, .stat-tile, .part-card, .part-cta, .quiz-sheet, .quiz-question, .loading-cinematic, .error-state, .mode-glider, and the rest of the 231. Inline styles are permitted only for genuinely computed values — the mode glider's translateX, a measured width. As a concrete anchor, .btn-primary is a 52px-minimum-height cyan fill in the display face at weight 800, with a spring hover lift (translateY(-2px) scale(1.02)) and a calm token-driven disabled state.

Typography and motion

The type system uses four self-hosted families with distinct jobs: Space Grotesk (--font-display) for headings at weights 700–800 — the layout comment calls it "a working designer's grotesk"; Inter (--font-inter) for body and UI, with the base body weight set boldly at 700; Lora (--font-lora) for lesson prose inside .markdown-content, where readability over long passages matters most, including an .editorial-dropcap treatment; and JetBrains Mono for code. The .markdown-content family of rules — headings, paragraphs, lists, blockquotes, tables, pre blocks — strictly consumes --text-primary and --bg-solid, a constraint added by the "Lite Mode AI Response Readability" fix after light-theme lesson text shipped too dim.

Motion is tokenized and consent-aware. The 28 keyframes cover the app's entire vocabulary — fadeUp, slideFromBottom, accentFlash, unlockPop, shake, correctPulse, confettiFall, shimmer — mostly riding the cubic-bezier(0.16, 1, 0.3, 1) house curve. Three separate @media (prefers-reduced-motion: reduce) blocks disable animation wholesale, and the JavaScript side cooperates: confetti passes disableForReducedMotion: true, haptics refuse to fire, and programmatic scrolling switches to behavior: "auto".

Performance as a design dimension

Unusually, the stylesheet treats device capability as a first-class theme axis alongside color. The html[data-perf] attribute — set pre-paint, kept current by ThemeApplier — gates the expensive effects per tier. On low, a universal rule strips every backdrop-filter (the comment identifies re-compositing blurs on scroll as "the single biggest lag source on weak GPUs"), hides the aurora layer, freezes ambient animations like .flame-flicker, and swaps the locked-part card's 12px blur for a plain opacity fade. On mid, aurora blobs keep their gradient wash but lose their infinite transform loop. On high, shadow tokens deepen for extra dimensionality. A parallel html[data-browser="firefox"] block applies the low-tier compositing treatment to Gecko specifically, where full-viewport backdrop-filter and mix-blend-mode are known jank sources — Chromium and Safari keep their glass. Sixteen media queries handle the responsive story: the sidebar takes over below 900px, .q-form compacts below 640px, and a series of min-width: 1024px blocks scale the hero (.hero__stage to 920px), typography, and input dimensions for large screens.

What the system optimizes for

Strip away the era-by-era renames and the constants of this design system are consistent: a single accent doing real signaling work; text contrast treated as non-negotiable (WCAG 2.1 AA is the stated bar, with 4.5:1 minimums baked into the token pairs); 44px minimum touch targets and visible focus rings; every visual cost gated by device tier and user preference; and a hard rule set — no purple, no gold, no hardcoded hex in components — that makes drift detectable by grep. The moods change the room's lighting; the tokens guarantee it is always the same room.
