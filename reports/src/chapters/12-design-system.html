12The Design System — Soft Pastel in Three Moods

One 3,188-line stylesheet is the design system: 108 custom-property tokens, 211 component classes, 28 keyframes, and a set of standing rules — most famously, no purple, anywhere, ever. This chapter documents both the Soft Pastel canon and the bolder, solid-color form the stylesheet has evolved into.

A design language and its evolution

The project's canonical description (in docs/AGENT_MEMORY.md) names the design language Soft Pastel: "cozy and colorful without costume" — cream paper washed with pastel sky, peach, mint, and rose, anchored by a clear sky-blue accent, expressed as "three moods of the same room": Paper (cream day), Ink (charcoal night), and Dusk (teal sunset evening). That canon was itself the survivor of rejected passes the changelog records candidly — a gray "Still Ink" pass the owner called bland, and a blurple pass rejected for violating the standing rule against violet.

The stylesheet has kept evolving since. The changelog entries of 2026-07-26 document two further passes that define what ships today: a curated two-theme pass that removed the third mood entirely ("Twilight Removal" — the twilight value was deleted from types/index.ts, lib/themes.ts, preferenceStore, the layout's theme script, and every globals.css selector), and a "Solid-Color Bold Electric" overhaul that purged every gradient and moved the accent from sky blue to vivid green. The result in the working tree is unambiguous: type Theme = "light" | "dark", and THEME_OPTIONS lists exactly two rooms — Paper, "Bright daylight with vivid green accent", and Ink, "Deep dark night with electric green accent". The three-mood structure remains the system's architecture (theme blocks keyed off data-theme, with every surface derived from tokens); the third mood is currently retired rather than architecturally impossible.

The token layer is 104 distinct custom properties defined in globals.css — a full set in :root for Paper and overrides in html[data-theme="dark"] for Ink, 176 definitions in total — plus the four font variables (--font-inter, --font-lora, --font-display, --font-mono) injected by next/font in the layout, for 108 tokens overall. Beyond colors, the sheet tokenizes shadows (--shadow-sm/md/lg, plus glow variants like --shadow-glow-accent), glassmorphism parameters (--glass-blur: 16px, --glass-saturate: 120%, --glass-edge), line heights (--leading-tight: 1.15 to --leading-relaxed: 1.75), durations (--dur-fast: 120ms to --dur-slow: 300ms), the scrim, and subject colors (--subject-physics through --subject-general) that tint the part-card chips. Tailwind's config maps its own color names onto these variables (accent: "var(--accent)", background: "var(--bg-primary)"…), so utility classes stay theme-correct without duplication.

The moods in practice

Paper is the :root default block, headed by a banner comment: bright off-white canvas #F8FAF9, white cards, deep-slate ink #0F172A, vivid green #00CC52 with white text on CTA fills. Ink — the default theme for new users ("Ink is the default room", per preferenceStore) — is a locked off-black #0B0E14 with electric green #00FF66 and dark-on-green buttons, its shadows deepened (--shadow-lg: 0 16px 40px rgba(0,0,0,0.6)) to keep elevation legible on a dark ground. Dusk, the teal-sunset evening mood, existed as a third data-theme block until the 2026-07-26 contrast pass concluded that two fully curated themes beat three partially distinct ones; the picker labels, the layout's pre-paint script, and the type union all now enumerate exactly Paper and Ink. Theme switching is instant and flash-free: the pre-paint script in layout.tsx sets data-theme before first paint, ThemeApplier keeps it and the theme-color meta in sync afterward, and every one of the 211 component classes reads only tokens, so a mood change is one attribute write.

The rules: one accent, no purple, no gradients

Two constraints have outlived every visual pass. The first is documented in AGENT_MEMORY as an owner's standing rule: no purple or violet anywhere. It has been enforced by action — the changelog records a dedicated "Purple/Violet Purge" that removed "40+ purple/violet/indigo color violations" introduced by a single PR across twelve files, re-skinning theme pickers, the logo, the manifest colors, badge tiers, share-card orbs, and confetti palettes. A grep of the current token sheet confirms compliance: the palette is greens, one orange, slate neutrals, and the red/green feedback pair. The second constraint is newer: the Solid-Color Bold Electric pass purged every linear, radial, repeating, and text-clip gradient, so all surfaces are flat fills with 2px solid borders and typography at weights 700–800. The related "one accent, used sparingly" de-slop rule keeps the green concentrated on primary actions, active states, and progress indicators rather than washed over everything.

Classes, not inline styles

The memory document calls inline style={{ ... }} soup "the #1 thing that makes this codebase look AI-generated" and mandates the component classes instead: .btn-primary, .btn-ghost, .btn-icon, .chip, .nav-link, .rl-card, .stat-tile, .part-card, .part-cta, .quiz-sheet, .quiz-question, .loading-cinematic, .error-state, .mode-glider, and the rest of the 211. Inline styles are permitted only for genuinely computed values — the mode glider's translateX, a measured width. As a concrete anchor, .btn-primary is a 52px-minimum-height flat green fill in the display face at weight 800, with a spring hover lift (translateY(-2px) scale(1.02)) and a calm token-driven disabled state.

Typography and motion

The type system uses four self-hosted families with distinct jobs: Space Grotesk (--font-display) for headings at weights 700–800 — the layout comment calls it "a working designer's grotesk"; Inter (--font-inter) for body and UI, with the base body weight set boldly at 700; Lora (--font-lora) for lesson prose inside .markdown-content, where readability over long passages matters most, including an .editorial-dropcap treatment; and JetBrains Mono for code. The .markdown-content family of rules — headings, paragraphs, lists, blockquotes, tables, pre blocks — strictly consumes --text-primary and --bg-solid, a constraint added by the "Lite Mode AI Response Readability" fix after light-theme lesson text shipped too dim.

Motion is tokenized and consent-aware. The 28 keyframes cover the app's entire vocabulary — fadeUp, slideFromBottom, accentFlash, unlockPop, shake, correctPulse, confettiFall, shimmer — mostly riding the cubic-bezier(0.16, 1, 0.3, 1) house curve. Three separate @media (prefers-reduced-motion: reduce) blocks disable animation wholesale, and the JavaScript side cooperates: confetti passes disableForReducedMotion: true, haptics refuse to fire, and programmatic scrolling switches to behavior: "auto".

Performance as a design dimension

Unusually, the stylesheet treats device capability as a first-class theme axis alongside color. The html[data-perf] attribute — set pre-paint, kept current by ThemeApplier — gates the expensive effects per tier. On low, a universal rule strips every backdrop-filter (the comment identifies re-compositing blurs on scroll as "the single biggest lag source on weak GPUs"), hides the aurora layer, freezes ambient animations like .flame-flicker, and swaps the locked-part card's 12px blur for a plain opacity fade. On mid, aurora blobs keep their gradient wash but lose their infinite transform loop. On high, shadow tokens deepen for extra dimensionality. A parallel html[data-browser="firefox"] block applies the low-tier compositing treatment to Gecko specifically, where full-viewport backdrop-filter and mix-blend-mode are known jank sources — Chromium and Safari keep their glass. Sixteen media queries handle the responsive story: the sidebar takes over below 900px, .q-form compacts below 640px, and a series of min-width: 1024px blocks scale the hero (.hero__stage to 920px), typography, and input dimensions for large screens.

What the system optimizes for

Strip away the era-by-era renames and the constants of this design system are consistent: a single accent doing real signaling work; text contrast treated as non-negotiable (WCAG 2.1 AA is the stated bar, with 4.5:1 minimums baked into the token pairs); 44px minimum touch targets and visible focus rings; every visual cost gated by device tier and user preference; and a hard rule set — no purple, no gradients, no hardcoded hex in components — that makes drift detectable by grep. The moods change the room's lighting; the tokens guarantee it is always the same room.
